Some Polymarket deposits get stuck for weeks, with no public explanation.

If your Polymarket account was created in the weeks before June 29, 2026, a deposit can land in a wallet that hasn't been created yet. The money is right there on the blockchain, but you can't withdraw it. Polymarket can release it with a single transaction, and it does, eventually. We couldn't find any public notice saying when, or why it happens. Every wallet, balance and release on this page can be checked on the Polygon blockchain. Account dates and user IDs come from Polymarket's own public profile service.

What actually goes wrong

Since May 2026, Polymarket accounts trade through a deposit wallet, a small smart contract made by Polymarket's wallet factory (0x0000…3Cc07). The address is worked out in advance, so the app can show it and take deposits before the contract exists. Polymarket creates the contract later.

The factory still has a recovery function, deployLegacy, that creates the old wallet. Only Polymarket can call it. As soon as it runs, the owner can withdraw as normal. Every release counted on this page is one of those calls.

Reported in public, no answer yet

    For the Polymarket team: how to clear the list in one go

    1. Download the list. Each row has the wallet, the balance, and either the Polymarket user ID your profile service returns for it or, where the owner posted it, the owner's address.
    2. Look up the signer address of each user ID in your database. For the wallets whose owner reported it publicly, it's already in the file.
    3. Call deployLegacy(owners, ids) on the factory with ids[i] = bytes32(owners[i]). It takes a list.
    4. Confirm it worked: eth_getCode(wallet) stops returning 0x, or just press "Check every wallet live" on this page.
    5. Then make it automatic, so the next person gets their money in minutes instead of weeks.

    How we got these numbers
    
  
    Stuck wallets. Every deposit into pUSD, Polymarket's currency, leaves an event on the chain naming the wallet that received it. We read every one of those since pUSD launched on March 31, 2026, . We kept the ones that hold pUSD, have no contract and have never sent a transaction, and then kept only those that Polymarket's profile service lists as an account created between the factory's first wallet (May 1, 2026) and the switch. Each one was checked again at a single block, and we found the transaction that first funded it. Wallets reported on GitHub were checked when the page was built.
    
  
    Freed wallets. The factory leaves an event every time it creates a wallet, and the event says which type. We listed every old-type wallet created after the switch and kept the ones that already held pUSD, USDC or USDC.e one block before they were created. The wait runs from the first deposit, or from the switch if the money arrived earlier, to the moment the wallet was freed.
    
  
    What this misses. The stuck list is a floor, not a ceiling. A wallet funded without a pUSD deposit, or one that isn't linked to a public Polymarket profile, only shows up if its owner reported it. For wallets whose owner isn't public we can't run the factory's own address check, but Polymarket can, from the user ID. Accounts created before the factory existed are left out, because they may use an older type of wallet. The figures are a snapshot of the moment we read the chain; the live check shows what has changed since.
